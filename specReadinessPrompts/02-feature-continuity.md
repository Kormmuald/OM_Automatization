## Проверяемая цепочка

Для каждой feature закрепи:
**общее видение → требования текущей feature → существующие компоненты и контракты →
изменения → интеграционные и регрессионные проверки → обновлённая память проекта**.

1. Общий неизменяемый source `preparation/docs/product-specs/local-bpmsoft-synchronizer/spec.md`
   явно указан в каждой spec и в AGENTS.md как видение всего инструмента.
   Он не отдельная feature и не заменяет конституцию.
2. У каждого текущего requirement есть qualified source reference и место в сквозном
   сценарии. Все OPS-001…013 распределены без потери смысла; 005 не создаётся.
3. Для 002–004 описаны предшественники: feature path, передаваемые capabilities,
   данные/identity, интерфейсные ограничения и evidence, необходимые перед использованием.
   Реальные артефакты и будущие ожидаемые контракты обозначены разными статусами.
   Не придумывать имена классов/API и не заявлять наличие ещё не написанного кода.
4. Указать, что добавляется текущим этапом, что переиспользуется и какие изменения
   потребуют анализа влияния на уже реализованное.
5. Закрепить накопительную регрессию и интеграционные проверки соединений, а не только
   тесты новой feature в изоляции. Требовать будущий test-plan.md на стадии Plan.
6. В 004 есть полный операторский/verification/Git-контур и общая приёмка MVP.
   Ни один ранний этап не зависит от позднего для собственных обязательных safety checks.
7. Архивация каждого завершённого этапа обновляет project memory; следующая feature
   использует проверенный код/контракты и эту память. Архивация сама не выполняет merge кода.
