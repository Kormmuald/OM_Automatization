# Спецификация функции: строгое read-only сравнение и неизменяемый план

**Feature**: `003-compare-read-only-plan`  
**Создано**: 2026-09-07  
**Статус**: Черновик — L2 Pilot  
**Неизменяемый исходник**: `preparation/docs/product-specs/local-bpmsoft-synchronizer/03-compare-plan-spec.md` (только чтение; не является feature directory)  
**Интеграции**: Jira и Confluence отключены; integration artifacts не создаются.

## Назначение и границы L2-пилота

Функция безопасно сравнивает заданную оператором валидную логическую пару Excel-книг с
зафиксированным состоянием заданной целевой BPMSoft, полученным только через разрешённые
read-only endpoints. Результат одного запуска — HTML-отчёт и неизменяемый
машиночитаемый план, оба построенные из единой канонической модели различий. Эта feature
не создаёт и не выполняет capability записи в BPMSoft.

Пилот ограничен одной явно выбранной парой книг, её `PairId`/baseline/template metadata и
одним `target fingerprint`, известными до запуска. Он не квалифицирует полный каталог,
не переносит результат на иные пары или цели и не подтверждает write allowlist.

## Пользовательские сценарии и проверка

### Пользовательская история 1 — Получить безопасный результат сравнения (Приоритет: P1)

Оператор выбирает валидную пару книг и целевую BPMSoft с ожидаемым `target fingerprint`.
Система выполняет исключительно разрешённые операции чтения, строит детерминированную
каноническую модель и выдаёт HTML-отчёт вместе с immutable plan либо безопасный результат
без действий/с блокерами.

**Почему этот приоритет**: это единственная самостоятельная ценность пилота и необходимая
безопасная предпосылка для какой-либо будущей, отдельной Apply-feature.

**Независимая проверка**: на фиксированных книгах и зафиксированном read-only snapshot
проверяется совпадение операций, количеств и blockers в отчёте и плане, а перехват HTTP
вызовов подтверждает отсутствие write calls.

**Сценарии приемки**:

1. **Дано** валидная пара книг, ожидаемый `target fingerprint` и доступные только
   allowlisted read-only endpoints, **Когда** оператор запускает сравнение, **Тогда**
   создаются HTML-отчёт и immutable plan из одной канонической модели, без HTTP-записей.
2. **Дано** пустая семантическая разница, **Когда** оператор запускает сравнение, **Тогда**
   создаётся проверяемый no-action результат, а не сессия Apply.
3. **Дано** неподдерживаемое намерение или неразрешимая зависимость, **Когда** оно
   обнаружено, **Тогда** результат содержит соответствующий именованный blocker, не
   предлагая обхода или действия записи.

### Граничные случаи

- Несовпадение `PairId`, baseline, метаданных шаблона, хеша книги или ожидаемого
  `target fingerprint` останавливает пилот до выдачи валидного плана.
- `Null`, `EmptyString`, значение и ссылка справочника различаются; некорректный
  непустой reference ID или неразрешённый `DraftRowToken` блокируют затронутое намерение.
- Цикл зависимостей, повторный producer или неразрешённая зависимость не допускают
  упорядоченного графа операций.
- Неизвестные тип или shape, а также подмена derived field, не угадываются и дают
  безопасную диагностику без секретов и исходных значений.

## Функциональные требования

- **FR-001 (CMP-001)**: Система ОБЯЗАНА валидировать пару книг через согласованный
  workbook contract и читать целевое состояние только через явный versioned allowlist
  read-only endpoints. Ни один HTTP write endpoint, method или побочный write-вызов не
  ДОЛЖЕН быть доступен из compare run.
- **FR-002 (CMP-002)**: Система ОБЯЗАНА определять канонические правила сравнения для
  каждого явно разрешённого поля `Desired*`; неуказанное поле НЕ ДОЛЖНО создавать операцию.
- **FR-003 (CMP-003)**: Для существующей сущности система ОБЯЗАНА использовать доказанную
  BPMSoft identity (server `Id`/schema или column `UId`) совместно с package-layer context.
  `Name` и `Code` допустимы лишь как display/diagnostic hints; global matching по ним
  запрещён. Предлагаемая зависимость по имени схемы/столбца допустима только в локальном
  draft graph.
- **FR-004 (CMP-004)**: Система НЕ ДОЛЖНА включать в план Delete, rename, изменение type,
  package или usage существующей сущности, index operations либо иной operation kind вне
  разрешённого списка. Каждое такое намерение ОБЯЗАНО завершаться именованным blocker.
- **FR-005 (CMP-005)**: Каноническая модель ОБЯЗАНА различать `Null`, `EmptyString` и
  `Value`, хранить типизированную каноническую форму и применять заданный приоритет
  reference: валидный `ReferenceRecordId`, затем однозначно resolved
  `ReferenceDraftRowToken`, иначе пустая ссылка.
- **FR-006 (CMP-006)**: Для каждой допустимой операции система ОБЯЗАНА выводить стабильный
  operation key, детерминированный dependency graph и полный порядок. `DEPENDENCY_CYCLE`,
  повторный producer или неразрешённая зависимость делают затронутую часть неисполняемой.
- **FR-007 (CMP-007)**: HTML-отчёт и machine-readable plan ОБЯЗАНЫ строиться ровно из
  одного экземпляра canonical model; их наборы операций, количества и blockers ДОЛЖНЫ
  совпадать.
- **FR-008 (CMP-008)**: Immutable plan ОБЯЗАН содержать версию формата, `RunId`, время
  создания, точные хеши обеих книг, template version, pair baseline, `PairId`, target и
  affected-state fingerprints, версию operation allowlist, полный упорядоченный набор
  операций и начальное значение либо материал выборки для browser verification.
- **FR-009 (CMP-009)**: План ОБЯЗАН быть записан как неизменяемый артефакт одного запуска.
  Любая будущая зависимая Apply-feature обязана проверять точные bytes и/или определённый
  semantic hash плана и НЕ ДОЛЖНА вызывать compare/diff logic для пересчёта различий.
- **FR-010 (CMP-010)**: Изменение любой связанной книги, её хеша, метаданных пары,
  `target fingerprint`, affected-state fingerprint, версии формата/allowlist либо любой
  операции ОБЯЗАНО инвалидировать план до каких-либо write calls будущей Apply-feature.
- **FR-011 (CMP-011)**: При пустой разнице система ОБЯЗАНА выпускать проверяемый
  no-action plan/report с доказательством отсутствия операций и НЕ ДОЛЖНА создавать
  Apply-сессию или подразумевать одобрение Apply.
- **FR-012 (CMP-012)**: HTML-отчёт о blocker ОБЯЗАН содержать безопасную причину,
  затронутые стабильные ключи, исходную ячейку или путь и способ устранения. Отчёт, план
  и диагностика НЕ ДОЛЖНЫ включать секреты, credentials или исходные чувствительные значения.
- **FR-013**: Система ОБЯЗАНА использовать следующие точные blocker identifiers, когда
  применимо: `RENAME_NOT_SUPPORTED`, `TYPE_CHANGE_NOT_SUPPORTED`,
  `PACKAGE_TRANSFER_NOT_SUPPORTED`, `DELETE_NOT_SUPPORTED`, `INDEX_SYNC_UNRESOLVED`,
  `INVALID_REFERENCE_ID`, `REFERENCE_TOKEN_UNRESOLVED`, `DERIVED_FIELD_TAMPERED`,
  `PAIR_MISMATCH`, `STALE_TARGET`, `UNSUPPORTED_SHAPE`, `DEPENDENCY_CYCLE`.

## Канонические сущности

- **Workbook pair**: две связанные книги с хешами, `PairId`, baseline и template metadata;
  единственный вход сравнения.
- **Read-only target snapshot**: нормализованное состояние BPMSoft, собранное исключительно
  через versioned endpoint allowlist и связанное с target/affected-state fingerprints.
- **Canonical model**: единственное представление входов, сравнений, операций,
  зависимостей, no-action результата и blockers, из которого производятся оба выхода.
- **Immutable plan**: машиночитаемая неизменяемая фиксация canonical model и её evidence;
  не является разрешением на Apply.
- **HTML report**: безопасное человекочитаемое представление той же canonical model.

## Валидация и приёмка L2-пилота

**Критерии успеха**:

- для заданной пары книг и ожидаемого `target fingerprint` результат успешно проходит
  validation входов и создаёт два согласованных артефакта либо согласованный no-action
  результат;
- контрактный перехват каждого HTTP-вызова доказывает, что вызов входит в read-only
  allowlist; попытка HTTP write является провалом;
- fixture-покрытие включает create/update/no-action, `Null`/`EmptyString`, приоритет
  ссылок, draft dependency и каждый перечисленный blocker;
- property-проверки подтверждают, что перестановка строк книг или порядка перечисления
  словаря не меняет семантику, хеш и порядок плана;
- независимая сверка подтверждает точное равенство операций, количеств и blockers отчёта
  и плана, а безопасная диагностика не содержит секретов или исходных значений.

**Stop criteria**: пилот немедленно останавливается без write-действий при выходе вызова за
read-only allowlist, `PAIR_MISMATCH`, `STALE_TARGET`, неизвестном shape, невалидной ссылке,
подмене derived field, неразрешимой зависимости, несовпадении отчёта и плана либо утечке
секрета/исходного значения в диагностике.

**Fallback**: сохранить только безопасный диагностический результат текущего compare run,
обозначить его невалидным для будущего Apply, не выполнять действий в BPMSoft и вернуть
оператору исходные книги без модификаций. Повторный запуск допустим только с вновь
валидированной парой и актуальным target snapshot.

**Решение человека**: после успешного пилота владелец результата вручную решает принять
доказательства сравнения, запросить исправления, остановить пилот или инициировать
отдельную future Apply-feature. Это решение не выводится из автоматического PASS и не
утверждает write allowlist.

## Вне области действия

- Apply, HTTP writes, browser write actions, подтверждение или расширение write allowlist,
  выполнение операций в BPMSoft и автоматическое исправление.
- Частичное одобрение плана, интерактивное редактирование отчёта, delete, rename,
  type/package/usage changes и любые index operations.
- Пересчёт diff в будущем Apply, обратная запись в Excel-книги, full-catalog qualification
  и перенос результатов пилота на другую пару книг или целевую систему.
- Создание в этом запуске `plan.md`, `tasks.md`, кода, checklist, research, data-model или
  quickstart: они относятся к последующим L2-шагам и могут создаваться только в этой же
  feature-папке после обязательного `/SpecKit Clarify`.
