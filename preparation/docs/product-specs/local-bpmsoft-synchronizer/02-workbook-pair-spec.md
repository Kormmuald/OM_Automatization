# Дочерняя спецификация 02: пара Excel-книг и контролируемое обновление

Статус: **кандидат; канонический шаблон v3 является только ограниченным справочным материалом**.

## Цель

Материализовать допущенное каноническое базовое состояние BPMSoft в логическую пару `BPMSoft.ModelCatalog.xlsx` + `BPMSoft.LookupCatalog.xlsx`, валидировать изменения и обновлять пару без потери неразрешённого локального намерения.

## Требования

- **WB-001** Точный набор листов, заголовков, столбцов, семантика редактируемых/производных полей и приоритет ссылок соответствуют `WORKBOOK_CONTRACT_VISION.md`.
- **WB-002** Обе книги создаются/заменяются атомарно из одного канонического базового состояния и общих `PairId`, `PullRunId`, `PairBaselineHash`, `BaselineTargetFingerprint`, `TemplateVersion`.
- **WB-003** Отрисовщик и парсер используют собственные типизированные ячейки, каноническую сериализацию и явные ключи строк; порядок представления Excel не влияет на семантику.
- **WB-004** Листы только для чтения защищены; смешанные листы не защищены. Парсер обнаруживает любое изменение нередактируемого поля независимо от защиты.
- **WB-005** Формула, внешняя ссылка, VBA, подключение, неизвестный столбец, недопустимый заголовок, повреждённые правила проверки/манифест/метаданные пары блокируют сравнение.
- **WB-006** Группировка `LookupValues` проверяет согласованность метаданных записей; идентичность записи содержит ровно один `RecordId|DraftRowToken`.
- **WB-007** Поля ссылок могут быть заполнены одновременно; корректный GUID имеет приоритет, некорректный непустой GUID блокирует обработку, затем допускается только однозначное разрешение токена, иначе ссылка пуста.
- **WB-008** Новая строка справочника создаётся только командой для Excel-книги, которая генерирует уникальный неизменяемый `DraftRowToken`; ручная подстановка токена блокируется.
- **WB-009** Перед выгрузкой записывается полный снимок `S_*` одного поколения затронутых рабочих листов. Старый снимок заменяется только после полной проверки нового.
- **WB-010** Обновление фактического состояния следует приоритету сервера; элемент, существующий только локально, сохраняется как `PotentiallyDeleted`, без автоматического `Removed` и намерения удаления.
- **WB-011** `Indexes` доступны только для чтения и сохраняются без потерь по контракту доказательств. Отдельная проверка проекции доказывает отсутствие вывода связи между `ActualIndexed` и членством.
- **WB-012** `INDEX_SYNC_UNRESOLVED` блокирует любой план/загрузку желаемого состояния индексов; отображение только для чтения сохраняется.
- **WB-013** Пара полного каталога должна пройти замыкание OOXML, цикл парсера, проекцию источника, проверку в настольном Excel без восстановления/с сохранением удобства работы и проверку масштаба.

## Приёмка и валидация

- Точный контрактный тест Excel-книг и регрессионный тест эталонного шаблона v3.
- Для несовпадения пары, изменённых ID/фактических значений, формул, внешних ссылок, недопустимых ссылок, конфликтующих групповых метаданных, повторяющихся токенов и неизвестных столбцов предусмотрены негативные фикстуры.
- Двукратная генерация из одного базового состояния даёт одинаковые канонические хеши листов.
- Настольный Excel: отсутствие восстановления, точные листы/данные, блокировка защищённой записи, смешанная редактируемость, изменение размера и существующие фильтры.
- Сверка источника с Excel-книгами по полному каталогу не содержит пропущенных/лишних строк; перечень неподдерживаемых элементов представлен явно.

## Вне области действия

Импорт из Google, пиксельно-идентичная устаревшая раскладка, формулы как бизнес-логика, безопасность на основе Excel-книг, изменение индексов и запись в BPMSoft.
