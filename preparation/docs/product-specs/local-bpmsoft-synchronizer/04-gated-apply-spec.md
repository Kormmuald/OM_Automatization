# Дочерняя спецификация 04: предварительная проверка записи на уровне операций, управляемый Apply и повторное чтение

Статус: **заблокировано до утверждения владельцем списка разрешённых операций записи и авторизации предварительной проверки в рабочей среде**.

## Цель

Разрешить минимальный безопасный набор операций создания/обновления только после ограниченной предварительной проверки для конкретной версии, выполнить точный одобренный план и доказать итоговое затронутое состояние.

## Предварительные условия

- Одобренный владельцем список разрешённых операций с областью действия на уровне полей.
- Отдельная авторизация для ограниченной предварительной проверки Write/Manage.
- Допущенный адаптер чтения, валидный неизменяемый план и актуальные отпечатки.
- Резервное копирование выполнено и подтверждено оператором.
- `INDEX_SYNC_UNRESOLVED` сохраняет исключение всех операций с индексами.

## Требования

- **APPLY-001** Пакет предварительной проверки для каждого кандидатного вида задаёт точную конечную точку/данные запроса, ожидаемый ответ, повторное чтение, разрешения, случаи ошибок и границу очистки/ручного восстановления до запуска.
- **APPLY-002** Обязательны позитивный случай и негативные случаи `permission denied`, устаревшее состояние, неоднозначная идентичность, тайм-аут/сбой HTTP, некорректный ответ и расхождение при повторном чтении.
- **APPLY-003** Вид операции включается в список разрешённых операций времени выполнения только после проверки доказательств и принятия владельцем; недокументированное поле остаётся запрещённым.
- **APPLY-004** Apply требует точный неизменяемый план, соответствующую версию списка разрешённых операций, подтверждение резервного копирования и одобрение плана целиком.
- **APPLY-005** Исполнитель следует только порядку плана, ведёт аудит по каждой операции и прекращает записи на первой ошибке.
- **APPLY-006** Операции удаления/отката/индексов отсутствуют в реестре конечных точек исполнителя.
- **APPLY-007** Структурный этап завершается требуемой последовательностью сохранения/компиляции/повторного чтения ровно в доказанной форме; этап справочников не начинается до PASS.
- **APPLY-008** Сгенерированные сервером ID схем/столбцов/реестров/записей извлекаются только доказанным путём ответа/повторного чтения. Отсутствующее или неоднозначное сопоставление останавливает выполнение.
- **APPLY-009** Сопоставление `DraftRowToken -> RecordId` уникально, проверяемо и используется для зависимых ссылок; резервный поиск по Name/Code запрещён.
- **APPLY-010** Финальное повторное чтение сравнивает каждое ожидаемое поле затронутого состояния; расхождение означает частичный/неуспешный результат без Git commit.
- **APPLY-011** Обратная запись только в Excel-книги — отдельная команда после Apply/повторного чтения, с неизменными хешами содержимого и аудитом сопоставления на уровне ячеек; вызовы BPMSoft отсутствуют.
- **APPLY-012** Повторная попытка не продолжает частично исполненный план автоматически; обязательны новое повторное чтение и решение человека.

## Кандидатные виды операций (не одобрены)

| Вид | Статус по умолчанию |
|---|---|
| Создать схему / назначить родителя / сохранить | `DENIED_PENDING_PREFLIGHT` |
| Создать собственный столбец | `DENIED_PENDING_PREFLIGHT` |
| Обновить `Required` собственного столбца | `DENIED_PENDING_PREFLIGHT` |
| Зарегистрировать существующую/новую схему справочника | `DENIED_PENDING_OWNER_SCOPE_AND_PREFLIGHT` |
| Создать строку справочника | `DENIED_PENDING_PREFLIGHT_AND_ID_PROOF` |
| Обновить значения строки справочника | `DENIED_PENDING_PREFLIGHT` |
| Добавить/изменить/удалить индекс | `DENIED_INDEX_SYNC_UNRESOLVED` |
| Удалить любую сущность/строку | `DENIED_OUT_OF_SCOPE` |

## Приёмка и валидация

- Наблюдатель конечных точек доказывает отсутствие записей до всех контрольных этапов и после внедрённой первой ошибки.
- Каждый включённый вид имеет проверенный набор доказательств и точный контрактный тест запроса/ответа.
- Идемпотентный повтор после достижения состояния не создаёт операций при новом сравнении.
- Инъекция ошибок покрывает сбой в каждой позиции операции и на границе каждого этапа.
- Успешный ограниченный запуск сверяет: план → аудит запроса → ответ/повторное чтение → проверки в браузере.

## Вне области действия

Автоматический откат/восстановление, частичное одобрение плана, повторные попытки без новой проверки состояния, удаления, изменения индексов, запись через браузер и неодобренные виды операций.
