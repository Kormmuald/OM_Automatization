## 3. Полнота требований

- Все верхнеуровневые FR-001–FR-022 сопоставлены как минимум с одним дочерним требованием или явным сквозным правилом.
- Все NFR-001–NFR-009 сопоставлены с задачами и валидацией.
- У каждого дочернего требования есть технический путь в плане:
  - `READ-*` → P1–P3;
  - `WB-*` → P4;
  - `CMP-*` → P5;
  - `APPLY-*` → P6–P7;
  - `OPS-*` → P8–P9.
- Ни одна задача не является единственным источником требования к продукту; задачи выводятся из спецификации/плана.
- Ни одна задача записи не может быть выполнена до контрольных этапов списка разрешённых операций/предварительной проверки владельцем.

## 4. Важные сверки

### Ограниченные доказательства и готовность полного каталога

Все артефакты утверждают, что шаблон v3 принят только как `VerifiedBoundedBaseline`. Полный каталог — это будущий допуск обобщённого считывателя и промышленного пути Excel-книг. Ни один артефакт не считает G5 полной приёмкой MVP.

### Устаревший источник и текущая безопасность

Устаревшие конечные точки/сопоставления являются кандидатами и основой фикстур. Фиксированные ограничения строк, резервный поиск идентичности по Name/Code, случайные ветви, клиентские ID/жёстко заданный пользователь, деструктивные удаления и смешанная логика Ajax/UI/домена классифицированы как `rewrite/drop/defer`. В плане нет шага прямого переноса.

### Поведение индексов

Во всех артефактах действует одно правило: членство только для чтения из `schema.indexes[].columns[].columnUId`, отдельный `ActualIndexed`, цели Own/Inherited, `INDEX_SYNC_UNRESOLVED` для плана/загрузки/применения. Задачи изменения индексов отсутствуют.

### Защита Excel-книг и приоритет ссылок

Все спецификации отражают решения владельца после G4: смешанные листы не защищены при жёстком контрольном этапе парсера; сортировка защищённого листа не требуется; оба поля ссылки могут существовать одновременно; некорректный непустой GUID блокирует обработку.

### Область исследования

План содержит только допуск обобщённого считывателя, постановку ограниченных задач по новым структурам и предварительную проверку записи для каждой операции. Он не повторяет широкое исследование домена, уже покрытое устаревшим решением/доказательствами.

## 5. Исключение учебного процесса: задачи до декомпозиции

Локальный курс обычно использует `plan → slices → tasks` и требует, чтобы каждая задача принадлежала части работы. Текущая задача владельца явно требует исполнимый бэклог задач и одновременно запрещает определения частей работы. Пакет разрешает это противоречие следующим образом:

- `tasks.md` — это бэклог полноты/зависимостей до декомпозиции, а не очередь исполнения агентом;
- он включает конкретные области изменений, зависимости, приёмку и валидацию;
- ни одна задача не выполняется до будущего пакета частей работы, одобренного владельцем;
- будущая декомпозиция должна назначить каждую задачу ровно один раз либо вернуть бэклог/план на ревью;
- после такого назначения анализ согласованности запускается повторно.

Это сохраняет контрольный этап курса без создания частей работы сейчас.

## 7. Правила предотвращения противоречий на следующем этапе

Будущее ревью не проходит, если какая-либо часть работы/задача/подсказка агенту:

- ссылается на G5 как на готовность полного каталога/записи;
- копирует устаревшее поведение идентичности/постраничной обработки/записи без текущего доказательства;
- добавляет изменение индексов, удаление, запись через браузер или автоматический откат;
- позволяет навыкам получать учётные данные либо одобрять/обходить план;
- считает защиту Excel-книги безопасностью парсера;
- отбрасывает неизвестные структуры или молча преобразует их;
- проводит широкое исследование вместо модели ограниченного допуска/предварительной проверки;
- реализует до именованных контрольных этапов владельца.
