# Спецификация спецификаций: управляемый локальный синхронизатор ОМ BPMSoft

Статус: **SDD candidate v1 — owner review required; implementation not authorized**.

## 1. Резюме

Технический оператор управляет синхронизацией объектной модели и lookup data между логической парой локальных Excel-книг и локальным BPMSoft через guided CLI. Система сначала читает и валидирует, затем строит strictly read-only immutable plan, допускает только явно разрешённый gated Apply, выполняет read-back и read-only browser verification и фиксирует проверяемый audit trail.

Исторический `SyncOM` используется для извлечения предметных сценариев и API-кандидатов. Новый продукт — controlled rewrite с typed domain core и новыми safety boundaries.

## 2. Пользователи и результаты

- Test operator: владелец на выделенном локальном стенде.
- Handoff operator: BPMSoft developer в своём Windows/local BPMSoft/desktop Excel environment.
- Reviewer: человек, проверяющий plan/evidence и принимающий gates.

Успешный outcome: независимый оператор проходит documented cycle без устных знаний владельца, а каждый change связан с workbook state, target state, approved immutable plan, read-back, browser evidence и Git result.

## 3. Сквозной сценарий

```text
настройка + интерактивный вход
-> валидация пары Excel-книг либо допуск выгрузки только для чтения
-> выгрузка состояния объектов и справочников и контролируемое обновление данных в Excel-книгах ОМ и справочников
-> валидация пары и целевых изменений
-> строгое сравнение только для чтения
-> HTML-отчёт + неизменяемый машиночитаемый план
-> запрос подтверждения, что человек выполнил резервное копирование БД локального стенда + одобрение плана целиком
-> поэтапная загрузка изменений на стенд в пределах списка разрешённых операций
-> полное повторное чтение затронутого состояния
-> проверка результата обновления данных в браузере без применения дополнительных изменений
-> опциональная запись в Excel-книги обновлённых данных стенда взамен временных значений, например draft GUID записей
-> явное подтверждение успешного выполнения
-> атомарный Git commit двух Excel-книг и безопасный при конфликтах push
```

Любой неуспешный контрольный этап завершает текущую ветвь без скрытых исправлений или расширения разрешений.

## 4. Область действия

- .NET 10/C# Windows CLI и локальный HTML-отчёт без кнопки Apply.
- Интерактивная аутентификация BPMSoft только в памяти.
- Типизированная доменная модель для пакетов, элементов рабочего пространства, слоёв схемы, столбцов, индексов/элементов, реестра справочников, записей/значений.
- Обобщённый считыватель только для чтения и единый контрольный этап допуска полного каталога.
- Валидация контракта, генерация и контролируемое обновление логической пары Excel-книг v1.
- Строгое сравнение только для чтения и неизменяемый план.
- Ограниченная предварительная проверка записи на уровне операций для списка разрешённых операций, одобренного владельцем.
- Управляемый контрольный этап для Apply только create/update, повторное чтение и опциональная обратная запись только в Excel-книги.
- Локальный журнал аудита, доказательств и запусков, проверка в браузере и финализация Git.
- Обязательные навыки Codex, которые оркестрируют CLI, но не принимают критические решения.

## 5. Вне области действия

- Удаление в BPMSoft, SQL-удаление, автоматическое резервное копирование/восстановление и автоматический откат.
- Добавление, изменение, удаление, загрузка или применение индексов до закрытия `INDEX_SYNC_UNRESOLVED`.
- Переименование существующих схем/столбцов, изменение типа существующего столбца, перенос пакета, изменения `usageType`, `isSimpleLookup`, целостности или каскадных правил.
- Google Sheets/Drive/Apps Script в качестве входных данных времени выполнения или целевой системы; импорт устаревших значений в локальный BPMSoft.
- Облачный BPMSoft, не-Windows среды и альтернативы Excel как поддерживаемый путь MVP.
- WPF/UI, действия записи через браузер, частичное одобрение плана, скрытое слияние.
- Создание частей спецификации или реализация в рамках этого пакета SDD.

## 6. Функциональные требования

- **FR-001 Приоритет источников.** Любое решение соответствует конституции приоритетов; устаревшее поведение классифицируется как `reuse/rewrite/drop/defer`, а не копируется молча.
- **FR-002 Список разрешённых операций чтения.** Операции выгрузки и сравнения используют только вход в систему и явно разрешённые конечные точки чтения; контрактный тест доказывает отсутствие записей.
- **FR-003 Полный считыватель.** Чтение коллекций использует явный детерминированный порядок, постраничную обработку, защиту от дубликатов, пропусков и бесконечного выполнения, а также телеметрию.
- **FR-004 Неизвестные структуры.** Неизвестная структура сохраняется без потерь как перечень неподдерживаемых элементов; она создаёт ограниченный по области блокер без догадок и скрытой потери данных.
- **FR-005 Допуск полного каталога.** Один контролируемый двойной проход полного каталога квалифицирует обобщённый считыватель по количеству, упорядоченным идентификаторам, хешам, пропускам/дубликатам, масштабу и перечню неподдерживаемых элементов.
- **FR-006 Пара Excel-книг.** Книги модели и справочников создаются и валидируются атомарно по контракту Excel-книг и общим метаданным пары.
- **FR-007 Контролируемое обновление.** Операция выгрузки создаёт проверяемый снимок `S_*` одного поколения и обновляет данные по принципу приоритета сервера, не удаляя автоматически строки, существующие только локально.
- **FR-008 Граница парсера.** Парсер блокирует изменённые поля идентичности, производные и служебные поля, недопустимые целевые значения, формулы/внешние ссылки, недопустимые ссылки, повторяющуюся идентичность и неподдерживаемые изменения.
- **FR-009 Сравнение только для чтения.** Операция сравнения не изменяет Excel-книги или BPMSoft и формирует отчёт и неизменяемый план из единой канонической модели.
- **FR-010 Связность плана.** План обновления ОМ и справочников связан с обеими книгами, шаблоном/базовым состоянием, целевой системой и затронутым состоянием; любое изменение делает Apply недействительным.
- **FR-011 Идентичность.** Существующие сущности связываются по серверной идентичности/слою пакета; новые строки используют `DraftRowToken`; резервный поиск по Name/Code запрещён.
- **FR-012 Порядок зависимостей.** Операции имеют стабильный ключ и детерминированный порядок зависимостей; одинаковые входные данные дают семантически идентичный на уровне байтов план.
- **FR-013 Контрольные действия человека.** До первой записи необходимы одобренный владельцем список разрешённых операций, подтверждение ручного резервного копирования и одобрение плана целиком.
- **FR-014 Ограниченный Apply.** Apply исполняет только разрешённые операции из точного плана, останавливается на первой ошибке и не выполняет откат или удаление.
- **FR-015 Подтверждение серверной идентичности.** Новые серверные идентификаторы принимаются только из доказанного ответа или однозначного повторного чтения; неоднозначность означает остановку.
- **FR-016 Повторное чтение.** Структурный этап должен пройти компиляцию и повторное чтение до этапа справочников; финальное повторное чтение сравнивает всё затронутое состояние.
- **FR-017 Обратная запись в Excel-книги.** Отдельная операция только для локальной среды допустима после успешного повторного чтения при неизменных хешах Excel-книг и записывает только доказанные идентификаторы/фактические значения.
- **FR-018 Проверка в браузере.** Все структурные изменения и определённая контрактом детерминированная выборка справочников проверяются только для чтения; критерий приёмки — 100 %.
- **FR-019 Артефакты запуска.** Папка запуска содержит безопасные журнал аудита, доказательства и журнал выполнения, а также необходимые метаданные версий; предыдущие запуски не удаляются.
- **FR-020 Финализация Git.** Только полный успех и явное подтверждение человеком создают атомарный Git commit двух Excel-книг с идентификатором запуска и хешем плана; конфликт автоматически не разрешается.
- **FR-021 Граница навыков.** Навыки запускают CLI, объясняют диагностику, проводят проверку в браузере и рабочий процесс Git только через контрольные этапы CLI; секреты и одобрения им не делегируются.
- **FR-022 Граница индексов.** `Indexes` остаётся доказательством только для чтения из `schema.indexes[]`; никакая операция с индексами не попадает в план при `INDEX_SYNC_UNRESOLVED`.

## 7. Нефункциональные требования

- **NFR-001 Безопасность:** учётные данные и данные сессии не сохраняются; для каждого типа запуска выполняется сканирование маркеров/секретов.
- **NFR-002 Детерминированность:** канонический порядок, сериализация и хеширование не зависят от состояния сортировки Excel или порядка перечисления входных данных.
- **NFR-003 Безопасное завершение при ошибке:** недопустимое, устаревшее, неоднозначное или неподдерживаемое состояние не превращается в отсутствие действий или успешное завершение.
- **NFR-004 Сохранность данных:** неподдерживаемые метаданные не пропускаются без записи в перечне и указания причины.
- **NFR-005 Идемпотентность:** повторный цикл после достижения целевого состояния не создаёт дублирующих изменений.
- **NFR-006 Аудит:** каждое решение по плану, применению и проверке трассируется к стабильному ключу операции и доказательствам.
- **NFR-007 Переносимость:** самодостаточный дистрибутив для Windows; секреты и локальные пути не вшиваются в пакет.
- **NFR-008 Удобство использования:** CLI с пошаговым сопровождением сообщает безопасную причину, способ устранения и следующее разрешённое действие.
- **NFR-009 Сопровождаемость:** ядро доменной модели не зависит от адаптеров Excel/BPMSoft/браузера; внешние контракты покрыты фикстурами.

## 9. Приёмка MVP

MVP может быть принят только при выполнении следующих условий:

1. оператор на чистой машине проходит поддерживаемый сквозной сценарий по регламенту выполнения;
2. допуск полного каталога даёт воспроизводимое базовое состояние либо конечный список ограниченных по области блокеров без скрытых пропусков;
3. каждый включённый вид записи имеет одобрение владельца и позитивные/негативные доказательства предварительной проверки для конкретной версии;
4. тесты с ошибками доказывают отсутствие записей до контрольных этапов и остановку после первой ошибки;
5. повторное чтение и проверка в браузере дают 100 % требуемых проверок;
6. успешный сценарий создаёт отслеживаемый Git commit двух Excel-книг; неуспешный или частичный сценарий его не создаёт;
7. сканирование секретов и валидация схемы доказательств проходят успешно;
8. операции с индексами отсутствуют, пока `INDEX_SYNC_UNRESOLVED` не закрыт отдельным решением.
