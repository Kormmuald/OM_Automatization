# Дочерняя спецификация 05: проверка, доказательства, Git и граница навыков Codex

Статус: **кандидат; рабочий процесс для промышленного применения не реализован**.

## Цель

Сделать каждый цикл проверяемым и передаваемым независимому оператору, не делегируя навыкам секреты, одобрения или критические решения по безопасности.

## Требования

- **OPS-001** Корень запуска использует иерархию дат + уникальный ID запуска; `audit/`, `evidence/` и журнал разделены, имеют метки времени и не перезаписывают предыдущий запуск.
- **OPS-002** Метаданные фиксируют версии приложения, шаблона Excel-книг, навыков Codex, BPMSoft, таблиц Excel + время изменения таблиц, псевдоним целевой системы, хеш плана и результаты контрольных этапов.
- **OPS-003** Схема доказательств запрещает всё по умолчанию и исключает password, ответ входа, cookie/CSRF, секреты Git и исходные значения справочников; автоматизированное сканирование маркеров/значений обязательно.
- **OPS-004** Проверка в браузере выполняется строго только для чтения и при необходимости использует отдельный интерактивный вход; навыки не получают учётные данные/данные сессии.
- **OPS-005** Все структурные операции полностью проверяются в браузере. Выборка справочников вычисляется до Apply из хеша плана + стабильного ключа операции: 10 % каждого вида, минимум 3, максимум 10, с покрытием новых/обновлённых записей при наличии.
- **OPS-006** Приёмка в браузере должна быть 100 %; отсутствующая/неуспешная проверка даёт `verification failed`, без исправления или успешного действия Git.
- **OPS-007** Повторное чтение через CLI остаётся авторитетным; доказательства из браузера дополняют, но не заменяют его.
- **OPS-008** Настройки Git содержат только provider, URL репозитория и branch; учётные данные остаются в диспетчере учётных данных пользователя.
- **OPS-009** После полного успеха и явного подтверждения человеком навык создаёт один commit обеих книг с ID запуска/хешем плана и выполняет push только при отсутствии конфликта.
- **OPS-010** Конфликт не разрешается автоматически; после ручного разрешения обе книги валидируются, а сравнение создаёт новый план. Сбой сети/аутентификации при push сохраняет локальный commit и ждёт явной повторной попытки.
- **OPS-011** Неуспешный/частичный цикл не создаёт commit Excel-книг; артефакты запуска никогда не добавляются в репозиторий Excel-книг.
- **OPS-012** Обязательные навыки: настройка, выгрузка, сравнение/проверка, сопровождение Apply, проверка в браузере, диагностика заблокированных входных данных, финализация Git. Они вызывают CLI и не реализуют параллельную бизнес-логику.
- **OPS-013** Пакет передачи содержит схему настроек, установку/обновление, регламент оператора, сценарий действий при ошибках и процедуру приёмки на чистой машине.

## Приёмка и валидация

- Модульные тесты/тесты свойств детерминированной выборки и граничные случаи 0/1/2/3/10/11/большое число операций.
- Доказательства контрольного списка браузера сверяют точные стабильные ключи и не содержат действий UI, допускающих запись.
- Интеграционные фикстуры Git покрывают успех, загрязнённое/несвязанное состояние, конфликт, сбой сети/аутентификации и признание плана недействительным после конфликта.
- Контрольные секреты, внедрённые в тестовую сессию, никогда не появляются ни в одном сохраняемом артефакте.
- Тест с человеком на чистой машине завершает документированный сценарий без устных указаний.

## Вне области действия

Хранение учётных данных, автоматическое разрешение конфликтов Git, автоматические повторные попытки push, очистка по сроку хранения, изменение данных через браузер и приёмка, выполненная агентом вместо человека.
