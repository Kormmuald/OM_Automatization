Статус: **пакет-кандидат для проверки владельцем; готов к обсуждению перед частями работы, но не к реализации**.

## Набор источников и приоритеты

Пакет основан на:

- [PROJECT_HANDOFF.md](../../PROJECT_HANDOFF.md), актуальная точка — раздел 16;
- [WORKBOOK_CONTRACT_VISION.md](../../WORKBOOK_CONTRACT_VISION.md);
- исторических черновиках в `../../SDD_DRAFTS/`;
- решениях владельца и независимых ревью в `../../READ_ONLY_RESEARCH_RESULTS/`;
- `../../../SyncOM/` только как историческом справочном источнике для чтения;
- указании владельца для текущей задачи SDD: контролируемая переработка, стратегия контрольного этапа допуска, ограниченное исследование записи, безопасное завершение при ошибке/сохранение неизвестных структур без потерь.

При конфликте действует приоритет источников из конституции. Старые черновики и исторические разделы передачи не переписываются; этот пакет показывает их актуализированную консолидацию.

## Что считается закрытым

- Logical workbook contract v1 и post-G4 corrections.
- Канонический шаблон v3 принят владельцем как `VerifiedBoundedBaseline` с ограничениями.
- Ограниченный явный порядок/постраничная обработка для `ActivityPriority` и `Lookup`.
- Ограниченное непустое сопоставление чтения индексов для двух простых индексов Test1.
- Контролируемая переработка и приоритет источников как стратегия текущей задачи SDD.
- Выгрузка полного каталога как будущий единый контрольный этап допуска обобщённого считывателя.

## Что не закрыто

- Полнота, масштаб и обобщение структур для всего каталога.
- Отпечаток целевой системы для промышленного применения, а также парсер/сравнение/неизменяемый план.
- Точные разрешения и семантика Write/Manage для любого вида операции.
- Доказательство `DraftRowToken -> RecordId` для промышленного применения.
- Изменение/загрузка индексов (`INDEX_SYNC_UNRESOLVED`).
- Поддержка LibreOffice уровня 2 и не-Windows сред.
- Рабочий процесс успешного Git-сценария для промышленного применения.

## Статус контрольных этапов

| Контрольный этап | Статус | Следствие |
|---|---|---|
| Полнота пакета спецификаций | `CANDIDATE PASS` | Можно проводить ревью владельцем |
| DoD спецификации для плана | `PASS WITH OPEN IMPLEMENTATION GATES` | План допустим как условная дорожная карта |
| Согласованность плана и задач | `CANDIDATE PASS` | Требуется ревью владельцем |
| Части работы | `NOT CREATED` | Следующий отдельный этап после решений владельца |
| Реализация | `NOT AUTHORIZED` | Код и действия в рабочей среде не начинать |

## Жёсткая граница этого пакета

В пакете нет `implementation-slices.md`, определений частей работы, подсказок агентам или пакетов оркестрации. `tasks.md` — бэклог до декомпозиции: задачи определены по входным данным/результатам/проверкам, но не назначены частям работы и не разрешены к исполнению. После ревью владельцем сначала создаётся отдельная декомпозиция на части работы, затем бэклог связывается с ними и повторно анализируется.
