## 2. Закрытые решения

### 2.1 Уже зафиксированные решения владельца

- Целевая система: локальный пакет Windows, .NET 10/C#, CLI с пошаговым сопровождением, локальный HTML-отчёт только для чтения.
- Рабочий процесс: валидация/чтение → сравнение → неизменяемый план целиком → явное одобрение → управляемый Apply → повторное чтение → опциональная обратная запись → аудит.
- Password/данные сессии только в памяти; навыки никогда не получают учётные данные.
- В MVP нет удаления/автоматического резервного копирования/отката/записи через браузер.
- Идентичность существующих сущностей определяется серверными IDs/UIds и контекстом пакета; новые строки — по `DraftRowToken`, без резервного поиска Name/Code.
- Логическая пара из двух Excel-книг и точная семантика листов/полей Excel-книги v1.
- Смешанные листы не защищены; парсер/сравнение является жёстким контрольным этапом. Листы только для чтения защищены; изменение размера/фильтр обязательны, сортировка заблокированного диапазона не требуется.
- `ReferenceRecordId` может существовать одновременно с `ReferenceDraftRowToken`; корректный GUID имеет приоритет; некорректный непустой GUID блокирует обработку.
- `Indexes` — доказательство только для чтения из `schema.indexes[]`; `ActualIndexed` отдельно; `INDEX_SYNC_UNRESOLVED` сохраняется.
- G5 принял шаблон v3 только как `VerifiedBoundedBaseline`.
- Выборка в браузере/порог 100 %, правила папки запуска/аудита и поведение Git при успехе/ошибке — как указано в конституции/спецификации.

### 2.2 Решения, принятые текущим явным указанием SDD

These are requirements of the present owner task, not agent assumptions:

- Стратегия миграции — контролируемая переработка устаревшего `SyncOM`.
- Приоритет источников: владелец/текущий контракт → воспроизводимые доказательства/ревью BPMSoft → характеристика устаревшего решения → статические устаревшие/внешние документы.
- Широкое исследование не проводится, когда существующие доказательства/фикстуры и характеристика устаревшего решения покрывают границу, не связанную с безопасностью.
- Выгрузка полного каталога — один будущий контрольный этап допуска обобщённого считывателя.
- Исследование записи ограничено каждым явно разрешённым видом операции.
- Неизвестные структуры сохраняются без потерь/безопасно завершаются ошибкой; без догадок и скрытой потери данных.
- В этой задаче не создаются части работы и реализация.

## 3. Разрешённые противоречия черновиков

| Утверждение раннего черновика | Решение в пакете-кандидате |
|---|---|
| Исследование чтения должно завершиться до первой дочерней спецификации, готовой к реализации | Дочерние спецификации можно писать условно уже сейчас; полный каталог — контрольный этап допуска считывателя, а не широкое предварительное исследование |
| Создание Excel-книг запрещено до широкого закрытия G2 | Историческое правило: G4/G5 позднее авторизовали и приняли только ограниченную поставку Excel-книг |
| План/задачи запрещены при открытых блокерах чтения | Заменено текущей явной задачей владельца подготовить план/задачи; исполнение остаётся управляемым контрольными этапами |
| MVP может включать создание/обновление индексов | Сейчас не разрешено; `INDEX_SYNC_UNRESOLVED` исключает весь план/загрузку/применение индексов |
| `DesiredIndexed` может позднее создавать план после проверки поля | Только после отдельного доказательства безопасности и решения владельца; текущие план/бэклог не содержат задачи изменения индексов |
| G5 означает готовность Excel-книг | Только ограниченная готовность справочного материала; для промышленной Excel-книги полного каталога нужен отдельный допуск |

## 4. Допущения (не решения)

- **A-01** Новое решение для промышленного применения будет размещено в `preparation/LocalBpmSoftSynchronizer/`, отдельно от `SyncOM`, `PrototypeReadOnlyPull` и `WorkbookDeliveryTool`, с границами проектов из плана реализации. Принятие пакета владельцем означает принятие этой структуры по умолчанию; последующее переименование не может менять границы.
- **A-02** Ядро доменной модели можно сохранить независимым от адаптеров Excel/BPMSoft, используя обычные интерфейсы .NET и неизменяемые записи; точные библиотеки остаются выбором уровня реализации.
- **A-03** Машиночитаемый план может использовать канонический JSON с явной версией схемы; библиотека сериализации и канонизация на уровне байтов требуют проектного доказательства до реализации.
- **A-04** Допуск полного каталога может завершиться PASS или конечным ограниченным списком блокеров; не предполагается, что он пройдёт с первой попытки.
- **A-05** Безопасная структурная диагностика может сохранить неизвестные структуры без исходных значений справочников; точная схема обезличивания должна быть проверена.
- **A-06** В BPMSoft 1.8 может существовать безопасное подмножество операций записи, но ни один вид не считается поддержанным до доказательств предварительной проверки и принятия владельцем.
- **A-07** Отдельный удалённый репозиторий Excel-книг подготавливается оператором при настройке; провайдер и URL не выбираются этим проектом.

## 6. Решения владельца, необходимые до декомпозиции

- **OD-01 Принятие SDD:** принять/скорректировать конституцию, верхнеуровневую спецификацию, пять дочерних спецификаций, условный план, бэклог, трассируемость и отчёт об анализе как единый пакет.
- **OD-02 Список разрешённых операций записи MVP:** выбрать точные виды операций и поля, допустимые для будущей ограниченной предварительной проверки. Текущее значение по умолчанию — ни одного.
- **OD-03 Область реестра справочников:** решить, может ли регистрация существующей/новой схемы войти в первое одобренное подмножество операций записи или остаётся отложенной.
- **OD-04 Область индексов:** рекомендуемое решение — исключить все изменения/загрузку индексов из MVP и сохранить отображение только для чтения. Без нового решения существующего блокера достаточно, и реализация индексов не планируется.
- **OD-05 Полномочия на предварительную проверку:** отдельно и явно авторизовать будущую предварительную проверку Write/Manage на уровне операции на одноразовой/локальной целевой системе; одного одобрения SDD недостаточно.
- **OD-06 Полномочия на этап декомпозиции:** после OD-01–OD-04 явно авторизовать создание определений частей работы. Текущая задача этого не делает.
